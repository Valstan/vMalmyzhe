### Блок «сегодня / вчера» — закрыт решением владельца 10.08

**Не делаем.** В подвале остаётся только штатный информер Метрики.

Владелец рассчитывал, что цифры динамики (сегодня / вчера / неделя / месяц —
как на длинном счётчике ЛайвИнтернета) приходят вместе со счётчиком. Проверено
в кабинете: **настройка информера — это одна галочка, без выбора периода**, и
информер отдаёт только сегодняшние три числа (просмотры, визиты, уникальные
посетители). Любой другой период — Reporting API, то есть отдельный
OAuth-токен, который надо выпускать и потом продлевать. Владелец решил, что
ради строки в подвале это не окупается.

Серверный код блока удалён (`getMetrikaStats`, тип `MetrikaStats`, проп
`stats`, переменная `YANDEX_METRIKA_TOKEN` в `.env.example`). Восстанавливать
заново не нужно, если решение переиграют: `git log -- web/src/lib/metrika.ts`.

⚠️ Уточнение, если вопрос вернётся: блок стоил **ноль** клиентской нагрузки —
запрос делал сервер, в браузер уезжали готовые числа. Отказ был из-за возни с
токеном, а не из-за веса страниц; **картиночный информер, наоборот, добавляет
по одному внешнему запросу на страницу.**

### Ревизия гейтов #104 — вскрыла отсутствие контура, а не дыру в правиле (PR #25)

**Автоматических гейтов на PR не было вообще.** `lint`/`typecheck` гонял вручную агент; единственная машинная проверка (`next build`) стояла в деплое — уже **после** мержа в `main`. «Гейты зелёные» означало «агент вспомнил запустить». Заведён **`ci.yml`**: `lint`, `typecheck`, `test` на каждом PR.

**Тестов поведения не было ни одного** — поэтому оба сегодняшних бага доехали до прода через законно зелёный контур. Чистая логика ingest вынесена в `web/src/lib/ingest.ts`, поверх неё **14 тестов** по следам этих багов.

Красные прогоны показаны: `test` → exit 1 (вернули баг `_status`), `typecheck` → exit 2, `lint` → exit 1 (rules-of-hooks). `eslint-plugin-react-hooks` подключён — класс, на котором сгорела Матрица, ловится.

⚠️ **Зелёные тесты не заменяют typecheck**: vitest транспилирует без проверки типов. Поймано вживую — `tsc` был красным полчаса, пока `pnpm test` рапортовал зелено.

**Осталось нетронутым сознательно:** все четыре собственных lint-правила стоят в `warn`, а `next lint` на warning'ах возвращает 0 — как гейт они бесполезны. ## Технические заметки

- **`draft: false` в Payload не публикует.** При `versions.drafts: true` состояние берётся из `data._status`; без него документ остаётся черновиком молча (201, id есть, публичный API отдаёт `totalDocs: 0`).
- **Сообщество публикует сборные дайджесты**: в одном посте несколько сюжетов через «✍» от разных источников, вложения лежат вперемешку. Брать все вложения подряд нельзя — в #77614 фото 3–5 были из сюжета про убийство в Паттайе, в #77631 шестое фото — митинг ВДВ в Калинино. Спорные картинки проверялись просмотром.
- **Повторная доставка того же `vkPostId` перекачивает медиа заново**: после двух прогонов 52 файла вместо 26. Это **не сироты** — на них ссылается история версий (`_posts_v`, `_posts_v_rels`), чистить SQL'ом нельзя, только через админку.
- Локальный `build` требует Postgres; служба `postgresql-x64-17` на машине владельца не стартует без прав администратора. Полная сборка проверяется в `deploy-prod.yml`.
- Реквизиты прод-бокса (хост, SSH-алиас, пользователь, пути, prod-env, адрес шлюза Сетки) — **только** в локальном неотслеживаемом `docs/INFRA.local.md` (D-038, 23.08). В handoff, письма и комментарии кода их больше не писать.
- Новые шрифты — локально в `web/public/fonts/`; фон — `web/public/patterns/ivory-town-emboss.webp`.
- Миграции Payload не генерировать вслепую: перед применением проверять SQL и drizzle-снапшот. Сегодняшние правки миграции **не требовали** — `publishedAt` и `_status` в схеме уже были.
