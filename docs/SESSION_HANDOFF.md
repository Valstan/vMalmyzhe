## Шаг 5 (2026-09-04): выход через ЕСА — PR #64–#67

Разобраны 4 письма brain после закрытия 03.09. Мандат по logout закрыт,
recommend по G231 закрыт, вопрос про `email` передан Сарафану с разбором.

- **`buildEndSessionUrl`** (`web/src/lib/auth/oidc.ts`): после локального
  logout — редирект на `end_session_endpoint` **из discovery**, с `client_id` и
  `post_logout_redirect_uri` в origin нашего `redirectUri` (не из
  `NEXT_PUBLIC_SERVER_URL`: тот подставляется из запроса, и возврат молча ушёл
  бы на страницу входа ЕСА). Поле в типе discovery — необязательное: старый
  деплой ЕСА, кэш до передеплоя, недоступность — выход деградирует до
  локального, cookie снимается **всегда**.
- ⚠️ **Гард открытого редиректора, сверх мандата:** `end_session_endpoint`
  приходит из сети, и это единственный редирект в потоке, после которого нет
  криптографической проверки (в `authorize`/`token` страхует подпись
  `id_token`). Origin эндпойнта обязан совпасть с origin issuer'а — иначе
  «Выйти» становится редиректором куда угодно. Красный прогон показан.
- **Контракт снят с кода ЕСА** (`setka/modules/radar_id/service.py`,
  `setka/web/api/radar_id.py`, read-only), не с письма: возврат разрешён по
  **origin** зарегистрированных `redirect_uri` (`post_logout_redirect_allowed`),
  несовпадение → 302 на `/login?logged_out=1`, не ошибка.
- **Подпись кнопки** — «Выйти из всех сервисов»: она гасит сессию всей
  экосистемы (D-072). ⚠️ Глазами на 390 px **не смотрели** — `build` требует
  локальный Postgres. Посмотреть на проде; при переполнении сократить.
- **`probe-prod.yml`** — read-only проба, кнопкой и еженедельно (пн 06:00 UTC):
  (1) приёмка выхода — `end_session_endpoint` есть, origin верный,
  `curl → 302 https://xn--80adkdyec4j.xn--p1ai/`; (2) дрейф-проба G231 — список
  коллекций **с кода**, на каждую обязана быть колонка в
  `payload_locked_documents_rels`; (3) признаки claims из журнала.
  Прогон 04.09: **колонок 6 = коллекций 6, чисто**.
- **Строка признаков claims** в `callback` (только «есть/нет», без значений) —
  чтобы ответить, доехал ли scope `email`. Мы **не зовём `userinfo` вовсе**,
  читаем всё из `id_token`; в сессию email кладём только при
  `email_verified === true`, поэтому пустой `email` в `/api/auth/me`
  неоднозначен — отсюда признаки в журнал.
- ⚠️ **Своя грабля, пойманная первым же прогоном** (PR #65): в конвейере
  `journalctl | grep | tail` статус берётся у **хвоста**, `tail` всегда 0 —
  `|| echo "данных нет"` не мог сработать ни разу, шаг молчал, и «не нашлось»
  читалось как «проверено и пусто». Родня G304.
- ⚠️ **Вторая, из двух прогонов подряд** (PR #67): 302 → и тут же `curl(28)`
  timeout на том же discovery ЕСА. Проба с одним выстрелом даёт ложную тревогу,
  а еженедельная проверка, которая кричит волком, перестаёт читаться — и тогда
  не поймает настоящий дрейф. Обоим запросам добавлены ретраи

  попыток остаётся красным. Финальный прогон
  ([33871597916](https://github.com/Valstan/vMalmyzhe/actions/runs/33871597916))

## Технические заметки

- **`draft: false` в Payload не публикует.** При `versions.drafts: true` состояние берётся из `data._status`; без него документ остаётся черновиком молча (201, id есть, публичный API отдаёт `totalDocs: 0`).
- **Сообщество публикует сборные дайджесты**: в одном посте несколько сюжетов через «✍» от разных источников, вложения лежат вперемешку. Брать все вложения подряд нельзя — в #77614 фото 3–5 были из сюжета про убийство в Паттайе, в #77631 шестое фото — митинг ВДВ в Калинино. Спорные картинки проверялись просмотром.
- **Повторная доставка того же `vkPostId` перекачивает медиа заново**: после двух прогонов 52 файла вместо 26. Это **не сироты** — на них ссылается история версий (`_posts_v`, `_posts_v_rels`), чистить SQL'ом нельзя, только через админку.
- Локальный `build` требует Postgres; служба `postgresql-x64-17` на машине владельца не стартует без прав администратора. Полная сборка проверяется в `deploy-prod.yml`.
- Реквизиты прод-бокса (хост, SSH-алиас, пользователь, пути, prod-env, адрес шлюза Сетки) — **только** в локальном неотслеживаемом `docs/INFRA.local.md` (D-038, 23.08). В handoff, письма и комментарии кода их больше не писать.
- Новые шрифты — локально в `web/public/fonts/`; фон — `web/public/patterns/ivory-town-emboss.webp`.
- Миграции Payload не генерировать вслепую: перед применением проверять SQL и drizzle-снапшот. Сегодняшние правки миграции **не требовали** — `publishedAt` и `_status` в схеме уже были.
