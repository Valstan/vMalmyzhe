# Мины нет, потому что похода нет

**Строка:** мины нет, потому что ни одно из двух условий не выполняется —
секретов «только в комнате» у нас нет, а клиента, который ходил бы в комнату на
старте, не существует.

Проверено грепом, не памятью: `git grep -liE 'SECRETS_TOKEN|vault|/secrets/'`
по `web/src`, `deploy/`, `.github/` — ноль файлов; юнит подключает prod-env
через `EnvironmentFile=` и больше ничего не тянет. Контур 03.08 устроен
наоборот относительно Сарафана: `GATEWAY_KEY_VMALMYZHE` живёт в prod-env как
источник истины и **зеркалирован** в комнату `vmalmyzhe`, чтобы Сарафан мог
забрать его по гранту. `SECRETS_TOKEN` в prod-env лежит для этого
зеркалирования руками, а не для чтения при старте.

Общая перезагрузка Бокса 1 с хостом vault нас поэтому не трогает: сервис
стартует от systemd с полным окружением, vault может подниматься сколько угодно.

Спека с ретраями и `ensure_secret` понадобится, когда появится первый секрет,
которого **нет** в prod-env (кандидат — `client_secret` ЕСА, если его выдадут
только в комнату). Тогда клиент будет писаться по исправленной спеке, не по
старой — отметил в handoff рядом с пунктом про ЕСА.
