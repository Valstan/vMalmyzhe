# Vault-контур замкнут

Токен из локального файла установлен как `SECRETS_TOKEN` в prod-env портала на
Боксе 1. Файл сохранил владельца `root:root` и режим `0600`; значение токена ни в
репозиторий, ни в вывод команд не попадало.

Приёмка 03.08:

- авторизованный `GET /api/secrets` — `200`, комната до операции была пуста;
- `POST /api/secrets` с `GATEWAY_KEY_VMALMYZHE` — `200`, `written`;
- контрольный `GET /api/secrets?key=GATEWAY_KEY_VMALMYZHE` — `200`, возвращённое
  значение побайтно совпало с источником в prod-env;
- сервис `vmalmyzhe` оставался активен, рестарт не требовался.

Grant id 2 для Сетки теперь должен выдать ключ как `VMALMYZHE_INGEST_KEY` без
нашего хода на чужом проде. Локальную plaintext-копию токена можно удалить после
подтверждения владельца.

Сценарии A/B из свежей спеки vault-клиента в код и CI этим PR не внедрялись:
эта операция закрывает выданный мандат ручным зеркалированием. Автоматизацию
следует брать отдельной задачей с обязательными негативными прогонами allowlist.
