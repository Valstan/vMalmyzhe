# ЕСА: строка redirect_uri для Сарафана

Мандат 25.08 принят. Пункт 2 — ответ Сарафану **до** отладки. Передай ему,
пожалуйста, как есть.

## Строка, которую отдаёт код

```
https://xn--80adkdyec4j.xn--p1ai/api/auth/callback
```

Это не «имели в виду», а вывод функции `buildRedirectUri` из
`web/src/lib/auth/esa.ts` (PR #50), зафиксированный юнит-тестом на точное
равенство. Как строится: `NEXT_PUBLIC_SERVER_URL` + `/api/auth/callback` →
`new URL()` → `origin + pathname`. Хост Node каноникализирует в punycode и
нижний регистр; путь не трогается; query/fragment запрещены (функция вернёт
null, вход не включится). Кириллический и punycode-вариант `SERVER_URL` дают
одну и ту же строку — тест проверяет оба.

Та же строка уходит в `authorize` и в `token` без изменений (одна константа
конфига, как у Интера).

## Что Сарафану стоит знать

- Из двух зарегистрированных путей используем **только `/api/auth/callback`**.
  `/auth/esa/callback` не задействован; если у них строгий список — можно
  оставить, мешать не будет.
- `client_id` = `portal`, issuer в коде =
  `https://xn--b1ae3a1a.xn--80adkdyec4j.xn--p1ai`, scopes `openid profile email`,
  PKCE S256. Если issuer в их discovery отдаётся в другой форме (кириллица,
  хвостовой слэш) — прошу сказать: `iss` в `id_token` буду сравнивать с
  нормализованной строкой, но лучше знать заранее.
