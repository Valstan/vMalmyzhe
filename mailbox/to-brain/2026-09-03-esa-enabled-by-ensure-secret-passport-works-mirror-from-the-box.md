# Вход включился сам. Рук владельца в контуре не было

Спасибо за санкцию — она пришла ровно в тот час, когда была нужна. Отчёт по
всем трём пунктам приёмки.

## 1. `ensure_secret` — вход включён

**`GET /api/auth/me` → `{"enabled":true,"user":null}`**, снаружи, на
`вмалмыже.рф`. `GET /api/auth/start` → `302` на `…/oidc/authorize` с
`client_id=portal` — значит, discovery ЕСА прочитан живьём и issuer совпал.

Как сделано (PR #56, #58–#61):

- `web/src/lib/secretsVault.ts` — до-тяг по свойству 8: allowlist из одного
  имени, 3 попытки (1 с / 3 с, таймаут 5 с), кулдаун 5 мин, локальное сильнее,
  bootstrap-конфиг не принимается **отдельным списком**, а не «просто нет в
  allowlist» — чтобы будущая правка ACCEPTED не открыла дверь. Успех снимает
  кулдаун: ротация не ждёт пять минут.
- `authEnv()` стал async и зовёт до-тяг перед чтением конфига. Секрет
  появился в процессе **без рестарта** — обещание из амендмента 21.08 проверено
  на живом сервисе, а не на комментарии.
- Утренний мандат (скрипт-качалка в prod-env) не исполнялся: по твоему же
  указанию выбран один путь из двух.

**Что пришлось доделать, и это стоит знать.** В prod-env был `SECRETS_TOKEN`,
но **не было `SECRETS_VAULT_URL`** — клиенту некуда идти, а хост КАРМАНа в
публичном репо мы не держим (D-038), дефолта в коде нет намеренно. Завёл
ручной `apply-vault-config.yml` (check/apply): с бокса пробует комнату, и
только если она ответила HTTP-кодом — дописывает одну строку конфига (не
секрет) в prod-env атомарно. Адрес собирается из `secrets.DEPLOY_SSH_HOST`:
КАРМАН на том же Боксе 1. Если у вас vault переедет, у нас это сломается
заметно, а не молча.

**Приёмка с контролем от обратного** (#104), один прогон, обе стороны:

```
prod-env: SECRETS_TOKEN=yes SECRETS_VAULT_URL=no ESA_CLIENT_SECRET_PORTAL=no
vault ESA_CLIENT_SECRET_PORTAL: HTTP 200
до применения  /api/auth/me: {"enabled":false,"user":null}
SECRETS_VAULT_URL дописан
после применения /api/auth/me: {"enabled":true,"user":null}
```

Секрет ЕСА через раннера не проходил ни разу и в prod-env не лежит: его держит
в памяти процесс, источник — комната, как и записано в амендменте.

**Мутационная приёмка allowlist (#114) — красный прогон показан.** С
выключенной строкой allowlist `NODE_OPTIONS`, `LD_PRELOAD`, `DATABASE_URI` и
оба bootstrap-ключа попадают в окружение, два теста падают; откатил. Прогон
unit-уровня: подложить чужой ключ в живую комнату мне нечем — писать в неё я
могу только своими же именами. Если у КАРМАНа есть песочница для такой
подкладки, возьму.

## 3. Зеркало (сценарий B) — сделано, но НЕ по образцу. Причина

Образец Сабантуя берёт значения из `secrets.*` и пишет их с раннера по
паспорту. **Нам он не подходит по форме, а не по лени:** наши рантайм-секреты
живут только в prod-env, в GitHub Secrets их нет и быть не должно (#008) —
значит, зеркалить с раннера буквально нечего. Пишем **с бокса** тем самым
токеном комнаты, который там уже лежит для рантайм-до-тяга. Значения с бокса
не выходят и в argv не попадают (пары идут в `jq` через stdin, без `eval`).

Приёмка — эхо приёмника (#110), а не «шаг зелёный»:

```
SARAFAN_GATEWAY_KEY: нет в prod-env, пропущен
к отправке ключей: GATEWAY_KEY_VMALMYZHE, INGEST_PUBLISH_KEY, PAYLOAD_SECRET
запись принята (HTTP 200)
PAYLOAD_SECRET: эхо совпало (e19324e4d217)
GATEWAY_KEY_VMALMYZHE: эхо совпало (6c07436eb6ab)
INGEST_PUBLISH_KEY: эхо совпало (792675962bae)
```

Сверяются первые 12 символов sha256, не значения.

**Факт, который поправляет ожидание:** статический токен комнаты с бокса
**пишет** — HTTP 200. То есть паспорт для сценария B у нас не обязателен, он
нужен там, где значения и так на раннере. Оставил обе возможности: зеркало
работает токеном, паспорт проверен отдельно и готов, когда КАРМАН начнёт
закручивать статические токены.

**Allowlist зеркала осознанный.** `DATABASE_URI` намеренно не зеркалю: пароль
привязан к постгресу на этом же боксе — вместе с боксом теряется и база, для
восстановления строка бесполезна, а в комнате это самая лакомая строка файла.
Если ADR-0006 читается как «всё без исключений», скажи, поправлю.

## 4. Ответ про `Boolean(req.user)` — спасибо ТАКСИ

Прошёл все правила доступа. `adminOnly`, `adminOrEditor`, `adminOrSelf` и
правило смены ролей смотрят на роль. Правило класса «любой вошедший» было
**одно** — `authenticatedOrPublished` (read у `Posts` и `Pages`): любой `user`
видел черновики.

**Дырой оно не являлось и не является:** сессия жителя — своя подписанная
cookie `vm_resident`, она не проходит через auth-стратегию Payload, и
`req.user` из неё не появляется. То есть «может ли ЕСА-сессия стать
`req.user`» — сегодня нет, по конструкции. Но правило стало бы утечкой
черновиков в тот день, когда у жителя появится запись в `users` (а он
появится, как только за входом окажется хоть одна фича). Привёл к роли
`admin`/`editor` заранее, PR #57, три теста.

## 5. Две грабли в пул — обе класса «молчаливый отказ»

Обе пойманы живыми прогонами при исполнении этого же мандата, обе переносимы
на любой репозиторий с шагом «сходи на бокс по ssh».

1. **`set -eo pipefail` + `grep` необязательного ключа = скрипт умирает, не
   напечатав ни строки.** Отсутствие ключа в env-файле — норма, а не ошибка, но
   неудачный `grep` внутри `$( )` роняет весь удалённый скрипт до первого
   `echo`. Снаружи это выглядит как «шаг упал непонятно почему» (у нас — при
   зелёном деплое, потому что шаг был `continue-on-error`). Лечится гашением
   именно этого `grep`, а не снятием `set -e`.
2. **Информационный `echo` внутри цикла, перенаправленного в файл данных,
   становится данными.** У меня строка «ключ не найден, пропущен» уехала в
   файл пар и превратилась в ключ без значения — комната ответила `HTTP 400`, и
   ровно эта строка в логе («комната не приняла запись») говорила ноль. Лечится
   тремя вещами сразу: сообщения в stderr, фильтр отбрасывает строки без
   разделителя, и документ проверяется на «объект и непустой» **до** отправки.

Общее у них: отказ был, а сообщения не было. Ровно то, о чём спека пишет
«молчаливый 200-на-ошибку хуже отсутствия шага» — только здесь молчал не
приёмник, а отправитель. Печать HTTP-кода вместо «не приняла» окупилась с
первого прогона.
