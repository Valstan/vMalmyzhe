# ЕСА переехала на вмалмыже.рф: отчёт о переезде и три переносимые находки

**Строка владельца (27.11):** перенести весь функционал регистрации посетителей
в системе малмыжских сайтов на сайт вмалмыже.рф — организовать там авторизацию
и список сервисов; всё, что висело на боксе Сарафана, перекинуть на бокс
вмалмыже.рф.

**Что сделано (27.11):**

- **ЕСА вынесена из Сарафана в отдельный сервис** `esa/` (FastAPI + SQLAlchemy
  async) в этом репозитории; живёт на боксе портала, слушает loopback
  `127.0.0.1:8010`. Это ровно та «проходная» из `unified-auth-concept.md`
  (отдельная маленькая программа, blast-radius изолирован) — но адрес у неё
  прежний, и потому клиенты не сломались.
- **Портал получил свои страницы**: `/login` (логин с паролем, регистрация,
  вход по ВК ID) и `/services` (каталог сервисов экосистемы). Проверка пароля
  идёт на сервере ЕСА по внутреннему API — пароль не ходит через браузер.
- **Адрес issuer'а не изменился** (`вход.вмалмыже.рф`), поэтому Тренер,
  Сабантуй, Казанская, ПОЗВОНИ, КАРМАН и портал работают без
  перерегистрации: переехали те же `client_id` и те же хэши секретов.
- **Данные переехали дампом** (`radar_users` + `oauth_clients`): 4 аккаунта
  посетителей и 6 OIDC-клиентов. `sub` перенесён как есть.
- **Живая приёмка на боксе пройдена целиком**: вход по паролю с портала (обе
  cookie — сессия портала и зонная сессия ЕСА), неверный пароль, OIDC-раунд-трип
  клиентом `portal` (код → токен → `sub` совпал), каталог на портале наполнен,
  внутренний API снаружи закрыт (404).
- **За владельцем:** переключение домена `вход.вмалмыже.рф` на бокс портала
  (DNS/edge) и живой вход по ВК ID глазами.

## Три находки, которые стоит записать в общий опыт

**1. Переезд identity-сервиса — это переезд двух вещей: адреса и носителя
идентичности.** Адрес issuer'а и набор клиентов можно оставить прежними, если
переносятся (а) хэши секретов клиентов, (б) `sub` пользователей. `sub` —
opaque-идентификатор, по которому соседние проекты (Казанская, ПОЗВОНИ)
узнают посетителя; пересчитал — разъедутся профили. Проверка переезда: не
«страница открылась», а *тот же* `sub` в `id_token` нового issuer'а.

**2. Внутренний API между двумя приложениями на одном боксе: loopback И общий
токен, и nginx не проксирует `/internal/*`.** Одного loopback мало: nginx
проксирует с localhost, то есть «внутренний» маршрут становится внешним для
всего, что прошло через nginx. Второй рубеж — общий токен в заголовке;
третий (дешёвый и надёжный) — `location /internal/ { return 404; }` в vhost'е.

**3. Грабля prod-env, записанного из PowerShell: CRLF.** Файл, собранный
`Set-Content -Encoding UTF8` на Windows, приезжает на Linux с `\r` в конце
значения. Символ невидим, а ломает HTTP молча: значение попадает в
`Set-Cookie`/заголовок, и клиент отвечает «Invalid HTTP request received».
Отдельная боль — BOM в начале файла: `source` такого env падает с
«No such file or directory». Оба символа снимаются на стороне отправителя
(`tr -d '\r'`, запись без BOM).

**4. У Джино TLS для наших доменов терминирует сам бокс, а edge — пробрасывает
SNI.** Это видно по сертификату, который видит посетитель: он выпущен на боксу
(certbot), а не на edge. Отсюда практический вывод для любого, кто переносит
домен на другой VPS у Джино: **сертификат надо выпускать на боксе**
(`certbot certonly --webroot -w /var/www/html -d <домен>`), а сертификат из панели
(edge) для этого домена не работает — edge отвечает на SNI «unrecognized name».
Два подвоха: (а) зона Джино перезагружается **не сразу** — после правки A-записи
авторитетные NS ещё какое-то время отдают старое значение, и это не откат, а
TTL; (б) плагин `webroot` сам nginx **не перезагружает** после продления — нужен
хук в `/etc/letsencrypt/renewal-hooks/deploy/`, иначе сервис до истечения
сертификата продолжит отдавать старый.

**И ещё одна, мелкая, но с тем же вкусом:** обработчик ошибок валидации
FastAPI, отдающий `exc.errors()` целиком, **роняет сервис на 500 вместо 422** —
в `ctx` ошибки лежит несериализуемое значение (в нашем случае байты). Клиент
получает «сервер сломан» вместо «плохой запрос», и по логам это выглядит как
падение приложения. Тело ответа собирается вручную: `loc`/`msg`/`type`.

## Что осталось за рамками

- Живой вход по ВК ID и приёмка владельцем — после переключения домена.
- Копия провайдера в Сарафане пока на месте (стенду нужен локальный
  экземпляр); снос — отдельная задача после приёмки. Правки в двух копиях
  разъезжаются молча (#087), поэтому в коде стоит пометка о каноничной копии.
- **Условия услуг** в каталоге сервисов остались в Сарафане: каталог на портале
  отдаёт список сервисов, а подробности по услугам пока пусты — источник надо
  либо перенести, либо перестать показывать.

## Решения, которые могут пригодиться соседям

Если соседний проект тоже заводит «проходную» (вход для жителей): держать её
**отдельным сервисом на боксе портала**, а не частью приложения-оператора —
переезд тогда стоит четыре таблицы, а не миграцию монолита. Публичный адрес
лучше не менять: смена issuer'а ломает всех клиентов разом.
