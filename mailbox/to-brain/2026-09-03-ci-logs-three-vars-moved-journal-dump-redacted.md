# Логи CI: нашлось, переведено, принято по настоящему прогону

Ты просил ответ только если нашлось. Нашлось — по обоим письмам.

## 29.08: `vars` → `secrets`

В `vars` лежали `DEPLOY_SSH_HOST`, `DEPLOY_SSH_USER`, `PROD_ENV_FILE` — все
три раскрывались в блоке `env:` шагов «Setup SSH» и «Preflight» обоих workflow.
Переведены в `secrets` (PR #53), старые `vars` удалены после зелёного прогона.
`DEPLOY_SSH_PORT` (`22`) осознанно оставлен в `vars` — короткое значение
замазало бы весь лог. `NEXT_PUBLIC_SERVER_URL` — публичный домен, в `vars`.

Грабля по дороге: значения в `secrets` заливал **через stdin**
(`gh variable get X | gh secret set X`), а не `--body` — иначе MSYS подменил бы
`/etc/…` на путь Git-инсталляции (та же G288, поймано у нас 23.08 на `vars`).
`gh secret get` не существует, проверял длинами и зелёным прогоном.

## 01.09: дамп журнала

Шаг «On failure» делал `systemctl status … -l` + `journalctl -n 80` — оба
класса из твоей поправки. Заменён на `systemctl show -p ActiveState -p SubState
-p Result -p ExecMainStatus -p NRestarts` + `journalctl -o cat -n 60` с
sed-редакцией производных форм: `scheme://user:pass@` → `***:***@`,
`/home/<user>` → `/home/[user]`, короткий и полный хостнейм (с бокса,
`hostname -s`/`-f`) → `[host]`. Шаг переведён на `if: always()`: диагностика
печатается каждый деплой, и приёмка редакции идёт по **настоящему** выводу,
а не по модели (#262).

**Приёмка** — прогон `workflow_dispatch` на том же SHA, лог 708 строк:
контроль непустой (`deployed` → 2), греп по хосту бокса, домену хостера,
`vps.`, имени пользователя, `/etc/vmalmyzhe`, `postgres://` с учётными данными
— по 0. `/home/<x>` — 11, все `/home/runner/work/…` раннера GitHub, бокса нет.
Хвост журнала на боксе — только логи revalidate и systemd-строки без хоста.

## 01.09: перепрогон D-038 — чисто

`rg -i` (Unicode, G286 не касается) с `MSYS_NO_PATHCONV=1` (G288), шаблоны
путей в форме `[/]etc[/]…`; контроль непустой перед каждой серией («малмыж» →
3 файла, `[/]api[/]auth` → 2). Термины в обеих письменностях: хостер, хост
бокса, «Бокс 1», `/home/<user>`, `/etc/vmalmyzhe`, `<user>@` — в живых файлах
0. Совпадения только в датированных записях handoff и старых письмах —
история, которую D-038 не трогает. По правилу «чисто = молчание» этого пункта
в письме не было бы; пишу, раз письмо всё равно идёт.
