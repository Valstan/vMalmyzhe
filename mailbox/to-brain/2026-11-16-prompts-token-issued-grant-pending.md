# Токен выпущен, выдача предложена — остался шаг владельца

**Строка:** «токен выпустил, грант #29 pending, раздел 503 — ждём политику приёма
в комнате-получателя».

## Что сделано (в порядке шагов мандата от 08.11)

1. **Адресат.** `GET /api/secrets/self` токеном службы, которая отдаёт
   `/api/prompts/section` (это служба КАРМАН, не наш портал — такого маршрута у
   портала нет) → **её** комната. Это **не** `karman` из шаблона мандата. Слаг —
   тот же, что в вашем письме от 09.11 назван для аналогичного случая; в наш
   публичный репозиторий его не пишем (D-038). Наша комната — `vmalmyzhe`,
   `canWrite: true`.
2. **Значение.** 32+ случайных байт, base64url (64 символа). Значение **нигде не
   напечатано**: генерировалось и ходило на боксе, в `argv` не попадало (тело
   запроса — файлом, заголовок — через curl-конфиг), в лог ушло только
   «значение на месте, read-back сошёлся по sha256».
3. **Запись в свою комнату.** `POST /api/secrets` → HTTP 200, ключ
   `PROMPTS_TOKEN_VMALMYZHE` в нашей комнате.
4. **Read-back.** `GET /api/secrets?key=PROMPTS_TOKEN_VMALMYZHE` → 200, значение
   на месте, sha256 совпал.
5. **Значение в prod-env.** Дописано (тем же значением, сверено по sha256; в git
   — только имя). Шаг зеркала в деплое дополнен этим именем, чтобы комната и
   prod-env не расходились. Перезапуск сервиса **не делали**: код токен пока не
   читает, а бокс не имеет запаса RAM.
6. **Предложение выдачи.** `POST /api/secrets/grants` → HTTP 201, **id 29**,
   состояние **pending**, адресат — комната службы.

## Что показывает состояние

- Проба `GET /api/prompts/section?project=vMalmyzhe` токеном раздела →
  **HTTP 503** («канал не настроен»). Ровно то, что предсказывает erratum №2:
  политика приёма ещё не объявлена, поэтому висящее предложение не становится
  активным задним числом.
- Список выдач **до** нашего шага: старых висших предложений по этому ключу не
  было (только ESA и ingest) — отзывать нечего. Появилась одна новая: #29.

## Осталось (три шага, наши, после одного вашего шага)

**Ваш шаг:** объявить политику приёма в комнате-получателе — «принимаю этот ключ
от комнаты `vmalmyzhe`». Кнопки «Принять» нет ни у кого, поэтому это и есть
тот единственный клик.

**Наши шаги после этого (по erratum №2, именно в таком порядке):**

1. **перепредложить** выдачу — новая выдача, она сразу уходит в `active`;
2. **отозвать** старое висшее предложение #29 — иначе оно путает в интерфейсе и
   выглядит как принятое;
3. **проверить** `GET /api/prompts/section?project=vMalmyzhe` токеном раздела →
   **200**, а не 503.

Только после этого в письме появится слово «канал поднят». Пока раздел не
читается, промты не забираем и **ничего не архивируем** — «не выполнил — не
архивируй».
