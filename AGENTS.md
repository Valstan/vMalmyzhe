# AGENTS.md — единые правила для AI-агентов «вМалмыже»

Этот файл — **единственный канонический вход для любой нейросети**: Claude Code, Codex,
Gemini CLI и других агентов. Инструкции конкретного инструмента могут дополнять его, но
не должны дублировать или переопределять проектные правила: копии расходятся молча.

## Состояние проекта

- **Что это:** сайт **вмалмыже.рф** — районный/городской портал (малмыж-кластер, вместе
  с ДК Малмыж и Калинино ЦКС).
- **Прод:** https://вмалмыже.рф/ — собственный VPS портфеля, nginx + TLS. Реквизиты
  бокса (имя, хост, порт, SSH, пути, prod-env) — **только** в локальном неотслеживаемом
  `docs/INFRA.local.md` на машине владельца; см. «Публичный репозиторий» ниже.
- **Стек:** Next.js 15 App Router + **Payload 3.75 + PostgreSQL** (стандарт экосистемы,
  стек Сабантуя), pnpm, standalone-сборка в CI.
- **Статус:** портал наполнен первым живым контентом из ВК (10 новостей в 6 рубриках,
  импорт 2026-08-03 через VK-шлюз Сарафана). Регулярный редакционный ритм не заведён.
- **Код сайта — в `web/`**, деплой-обвязка — в `deploy/`.
- Карточка проекта: `../brain_matrica/projects/vMalmyzhe.md`; концепт кластера —
  `../brain_matrica/docs/plans/malmyzh-sites-rebuild-concept.md`.
- Память последней сессии: `docs/SESSION_HANDOFF.md`.

`brain_matrica` разрешено только **читать**. Никогда не изменяй и не коммить файлы в
`../brain_matrica`. Предложения Мозгу оформляй в `mailbox/to-brain/*.md` этого репозитория.

## Начало и завершение работы

В начале работы, в этом порядке (сначала синхронизация, потом чтение памяти — pool #032):

1. Синхронизируй **только свой** репозиторий: `git fetch`, затем fast-forward при
   чистом дереве. Незакоммиченное или не-ff — сообщи и не форсируй. Соседние
   репозитории, включая `brain_matrica`, — **только чтение**: никаких `fetch`, `pull`,
   `checkout` и иных синхронизирующих/изменяющих команд (проект или Мозг могут
   одновременно работать в локальной копии, в т.ч. иметь ещё не запушенную почту).
2. Прочитай входящий mailbox в **двух каналах** (набор = объединение источников):
   - локально: `../brain_matrica/mailboxes/vMalmyzhe/from-brain/*.md`
     (**не** `DRAFTS/`, **не** `ARCHIVE/`);
   - на GitHub `main` того же проекта: те же пути через API/веб (raw), **без
     clone/fetch/pull**.
   Свежесть — по каждому письму и пути: одноимённое письмо различается → историей
   **именно этого пути**: незакоммиченная локальная версия — свежее; иначе последний
   локальный коммит файла vs последний коммит пути на GitHub; порядок не определяется —
   прочитать обе версии, явно отметить конфликт, **не перезаписывать**.
3. Доложи сводку писем.
4. Прочитай `docs/SESSION_HANDOFF.md`, проверь `git status` и последние коммиты.

В конце значимой работы обнови `docs/SESSION_HANDOFF.md`, сохрани всё через PR и оставь
свой репозиторий чистым и синхронизированным.

## Mailbox: асимметричные почтовые ящики (ADR-0001 v3)

Каждая сторона пишет только в свой репозиторий.

| Направление | Кто пишет | Где |
|---|---|---|
| `brain → вМалмыже` | brain | `../brain_matrica/mailboxes/vMalmyzhe/from-brain/*.md` — мы только **читаем** (два канала: локально + GitHub `main` через API, см. «Начало и завершение работы») |
| `вМалмыже → brain` | мы | **`mailbox/to-brain/*.md`** в этом репо, через PR |

Compliance: `mandate` → MUST, `recommend` → SHOULD (отказ обосновать письмом),
`suggest` → MAY. Письма без поля `compliance`: `kind: directive` → MUST, `kind: idea` →
SHOULD. Требование, происхождение которого — **владелец**, старше рекомендации Мозга
(постулат 36); расхождение фиксируй письмом, а не молча.

Формат исходящего письма `mailbox/to-brain/YYYY-MM-DD-slug.md`:

```yaml
---
from: vMalmyzhe
to: brain
date: YYYY-MM-DD
topic: ...
kind: idea | question | feedback | report | request
compliance: suggest | recommend | mandate   # для kind=idea
urgency: low | normal | high
---
```

## Гейты и деплой

- Гейты перед PR, если трогался код: `corepack pnpm lint && corepack pnpm typecheck &&
  corepack pnpm test && corepack pnpm deadcode`. `ci.yml` гоняет те же четыре на
  каждом PR; `deadcode` (knip) валит неиспользуемый экспорт — константы только для
  модуля не экспортировать.
- **`build` требует локальный Postgres** — Payload обращается к БД на пререндере; если
  поднять его нельзя, скажи об этом прямо и положись на сборку в `deploy-prod.yml`,
  не выдавая непроверенное за проверенное.
- **Зелёные тесты не заменяют typecheck**: vitest транспилирует без проверки типов,
  `tsc` ловит то, чего тесты не видят. Гонять оба.
- **Новый гейт считается заведённым только после показанного красного прогона** (#104).
  Добавил проверку — сломай нарочно, убедись, что она падает с ненулевым кодом, откати.
  Гейт, ни разу никого не поймавший, — кандидат в пустышки.
- Мерж в `main` → **авто-деплой на прод** (`deploy-prod.yml`). У воркфлоу `paths-ignore`:
  `docs/**`, `**.md`, `.github/**`, `.claude/**` — эти файлы пересборку **не** триггерят.
- **Миграции схемы Payload — вручную ДО деплоя** через `apply-migration.yml`
  (workflow_dispatch, migration-guard #017), затем деплой. Миграции не генерировать
  вслепую: проверять SQL и drizzle-снапшот.
- Секреты живут вне репо (#008): прод — prod-env бокса (подключается systemd через
  `EnvironmentFile=`), локально — `web/.env`. Шаблон — `web/.env.example`.
- **Сканер секретов** (gitleaks) — шаг внутри `gates` на каждом PR (`.gitleaks.toml`:
  дефолт + VK/Telegram/наши env-имена/postgres-URI). Красный показан 23.08 (PR #45).
  Нашёл секрет в истории — **сначала отозвать у эмитента**, потом чистить файл;
  историю не переписывать (#060: ротация доминирует переписывание).

## Git и совместная работа нескольких агентов

- `main` защищён логически: ветка → коммит → push → PR → **squash merge**. Прямой push в
  `main`, force-push и `reset --hard` запрещены.
- Один агент — одна задача — своя ветка. При одновременной работе — отдельный
  `git worktree`; двух пишущих агентов в одном рабочем дереве не запускать.
- Перед правкой проверяй `git status`. **Незнакомые изменения считай чужими**: не удаляй,
  не форматируй попутно, не включай в свой коммит и не прячь в stash.
- Не переключай ветку в рабочем дереве, которое может использовать другой агент.
- Объявляй границы задачи и файлов в описании PR. При пересечении границ второй агент
  ждёт merge первого и обновляет свою ветку до начала правок.
- Один PR — одна задача. Коммиты — Conventional Commits.
- После обрыва восстанавливай фактическое состояние из Git/PR/handoff, не повторяй
  действия по памяти (D-066: отдельной команды для этого нет).
- **Текст не сочиняется внутри командной строки** (D-046). Содержимое пишется
  инструментом записи файлов, команде отдаётся путь: `git commit -F msg.txt`,
  `gh pr create --body-file body.md`, `psql -f q.sql`, `curl --data-binary @body.json`,
  на удалённый хост — `scp`. Heredoc и многострочные аргументы запрещены: текст в
  команде проходит до четырёх парсеров (кавычки инструмента, локальный шелл, удалённый
  шелл, кодовая страница), и отказ выглядит как ошибка в данных, а не в доставке.
  Триггер — перенос строки, backtick, `$`, кавычка или не-ASCII в собственной команде:
  остановись и перепиши через файл, не экранируй. Короткие однострочные ASCII-команды
  под правило не попадают.

**Git — механизм координации между моделями.** Чат одной модели не является источником
истины для другой: долговечные решения живут в документации и ADR, состояние
незавершённой работы — в `docs/SESSION_HANDOFF.md`, история — в коммитах и PR.

## Как читать памятки `.claude/commands/`

Файлы `.claude/commands/*.md` (`start`, `close_session`) — исполняемые
памятки, применимые **любому** агенту, несмотря на имя каталога. Правила перевода на
язык, независимый от инструмента:

- поле `allowed-tools:` — игнорировать, это конфигурация одного инструмента;
- `/команда` — читать как «выполни шаги, описанные в файле `.claude/commands/команда.md`»;
- гейт, описанный через конкретный инструмент (например «спроси через `AskUserQuestion`
  перед необратимым действием») — читать как «задай вопрос и дождись явного ответа».

**Форма любая, шаг обязателен.** Отсутствие у агента named-инструмента не отменяет шаг:
это предохранитель, а не фича вендора.

## Какие AI-файлы хранить в Git

Коммитить: `AGENTS.md` (источник истины), `CLAUDE.md` и `GEMINI.md` (короткие адаптеры),
`.claude/commands/` и `.claude/settings.json` (общие безопасные команды и разрешения),
`docs/`, `mailbox/`, `web/.env.example`.

Не коммитить: `.claude/settings.local.json` (локальные разрешения), кэши и сессии
`.codex/`, `.gemini/`, `.env*` с реальными значениями, ключи, токены, логи, временные
планы вне проектной документации.

Секреты не должны попадать в репозиторий даже под защитой `.gitignore`.

## Публичный репозиторий — тоже recon-поверхность (D-038)

Репозиторий **публичный с 2026-08-17** (D-030). Правило сформулировано через
**свойство файла**, а не через канал публикации — запрет «не светить на витрине»
перестал защищать в день, когда витриной стал сам репозиторий (#189):

- В **отслеживаемые файлы** (код, workflows, `deploy/`, доки, памятки, `.env.example`,
  письма) **не кладём**: IP и хостнеймы боксов, имена боксов («Бокс N»), имя хостера
  и его панели, прод-порты в описании прода, пути на сервере (`/etc/…`, `/home/…`,
  пути релизов и медиа), SSH-алиасы, имена ключей и логины, состав жильцов бокса,
  внутренние URL чужих прод-сервисов (шлюз Сетки и т.п.).
- Где им место: секреты и адреса — в `web/.env` / prod-env / `vars` и `secrets`
  репозитория; человекочитаемые реквизиты бокса — в `docs/INFRA.local.md`
  (в `.gitignore`, живёт только на машине владельца). Код и workflows берут их из
  окружения **без дефолтов-литералов** — пустое значение должно падать, а не
  подставлять адрес.
- Публичный домен витрины (`вмалмыже.рф` и punycode), номер счётчика Метрики,
  `localhost`-дефолты для dev — не реквизиты, держать можно.
- Датированные записи (`docs/SESSION_HANDOFF.md` «Что сделано (дата)», отправленные
  письма в `mailbox/to-brain/`) — **не переписывать**: это история, и чистка ничего
  не отзывает (всё уже в git-истории и форках). Новых деталей туда не добавлять.
- Граница честно: вычистка — гигиена на будущее, а не устранение утечки. Адреса
  владелец менять не стал (D-038) — остаточный риск принят сознательно.

## Чего не делать

- Не писать и не коммитить в `../brain_matrica` — он read-only.
- Не ходить на чужие прод-боксы (ADR-0009 «чужой прод — не наш прод»). Наш —
  в `docs/INFRA.local.md`. Пересечение границы возможно только с явного разового
  разрешения владельца, и его надо зафиксировать письмом в `mailbox/to-brain/`.
- Не городить обходы недостающих доступов: неработающий канал, замаскированный обходом,
  живёт годами. Отсутствие доступа — повод написать письмо, а не изобрести путь мимо.
- Не публиковать автоматически контент из ВК: ingest по умолчанию создаёт **черновик**
  (mandate 07-26). Явная публикация — осознанное действие оператора флагом `publish`.
- Не выдавать непроверенное за проверенное: если гейт не удалось прогнать, это надо
  сказать словами.
