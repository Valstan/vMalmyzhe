# AGENTS.md — единые правила для AI-агентов «вМалмыже»

Этот файл — **единственный канонический вход для любой нейросети**: Claude Code, Codex,
Gemini CLI и других агентов. Инструкции конкретного инструмента могут дополнять его, но
не должны дублировать или переопределять проектные правила: копии расходятся молча.

## Состояние проекта

- **Что это:** сайт **вмалмыже.рф** — районный/городской портал (малмыж-кластер, вместе
  с ДК Малмыж и Калинино ЦКС).
- **Прод:** https://вмалмыже.рф/ — **Бокс 1** (`831d0ce99bdf.vps.myjino.ru`), порт
  **:3004**, nginx + TLS (LE через панель Джино).
- **Стек:** Next.js 15 App Router + **Payload 3.75 + PostgreSQL** (стандарт экосистемы,
  стек Сабантуя), pnpm, standalone-сборка в CI.
- **Статус:** портал наполнен первым живым контентом из ВК (10 новостей в 6 рубриках,
  импорт 2026-08-03 через VK-шлюз Сарафана). Регулярный редакционный ритм не заведён.
- **Код сайта — в `web/`**, деплой-обвязка — в `deploy/`.
- Карточка проекта: `../brain_matrica/projects/vMalmyzhe.md`; концепт кластера —
  `../brain_matrica/docs/plans/malmyzh-sites-rebuild-concept.md`.
- Память последней сессии: `docs/SESSION_HANDOFF.md`.

`brain_matrica` разрешено только **читать**. Никогда не изменяй и не коммить файлы в
`../brain_matrica`. Предложения Мозгу оформляй в `mailbox/to-brain/*.md` этого репозитория.

## Начало и завершение работы

В начале работы, в этом порядке (сначала синхронизация, потом чтение памяти — pool #032):

1. Синхронизируй **свой** репозиторий: `git fetch`, затем fast-forward при чистом дереве.
   Незакоммиченное или не-ff — сообщи и не форсируй.
2. Синхронизируй `../brain_matrica` только fast-forward и только при чистом дереве.
3. Прочитай входящие в корне `../brain_matrica/mailboxes/vMalmyzhe/from-brain/*.md`
   (**не** `DRAFTS/`, **не** `ARCHIVE/`) и доложи сводку.
4. Прочитай `docs/SESSION_HANDOFF.md`, проверь `git status` и последние коммиты.

В конце значимой работы обнови `docs/SESSION_HANDOFF.md`, сохрани всё через PR и оставь
оба репозитория синхронизированными и чистыми.

## Mailbox: асимметричные почтовые ящики (ADR-0001 v3)

Каждая сторона пишет только в свой репозиторий.

| Направление | Кто пишет | Где |
|---|---|---|
| `brain → вМалмыже` | brain | `../brain_matrica/mailboxes/vMalmyzhe/from-brain/*.md` — мы только **читаем** |
| `вМалмыже → brain` | мы | **`mailbox/to-brain/*.md`** в этом репо, через PR |

Compliance: `mandate` → MUST, `recommend` → SHOULD (отказ обосновать письмом),
`suggest` → MAY. Письма без поля `compliance`: `kind: directive` → MUST, `kind: idea` →
SHOULD. Требование, происхождение которого — **владелец**, старше рекомендации Мозга
(постулат 36); расхождение фиксируй письмом, а не молча.

Формат исходящего письма `mailbox/to-brain/YYYY-MM-DD-slug.md`:

```yaml
---
from: vMalmyzhe
to: brain
date: YYYY-MM-DD
topic: ...
kind: idea | question | feedback | report | request
compliance: suggest | recommend | mandate   # для kind=idea
urgency: low | normal | high
---
```

## Гейты и деплой

- Гейты перед PR, если трогался код: `corepack pnpm lint && corepack pnpm typecheck &&
  corepack pnpm build`. **`build` требует локальный Postgres** — Payload обращается к БД
  на пререндере; если поднять его нельзя, скажи об этом прямо и положись на сборку в
  `deploy-prod.yml`, не выдавая непроверенное за проверенное.
- Мерж в `main` → **авто-деплой на прод** (`deploy-prod.yml`). У воркфлоу `paths-ignore`:
  `docs/**`, `**.md`, `.github/**`, `.claude/**` — эти файлы пересборку **не** триггерят.
- **Миграции схемы Payload — вручную ДО деплоя** через `apply-migration.yml`
  (workflow_dispatch, migration-guard #017), затем деплой. Миграции не генерировать
  вслепую: проверять SQL и drizzle-снапшот.
- Секреты живут вне репо (#008): прод — `/etc/vmalmyzhe/vmalmyzhe.env`, локально —
  `web/.env`. Шаблон — `web/.env.example`.

## Git и совместная работа нескольких агентов

- `main` защищён логически: ветка → коммит → push → PR → **squash merge**. Прямой push в
  `main`, force-push и `reset --hard` запрещены.
- Один агент — одна задача — своя ветка. При одновременной работе — отдельный
  `git worktree`; двух пишущих агентов в одном рабочем дереве не запускать.
- Перед правкой проверяй `git status`. **Незнакомые изменения считай чужими**: не удаляй,
  не форматируй попутно, не включай в свой коммит и не прячь в stash.
- Не переключай ветку в рабочем дереве, которое может использовать другой агент.
- Объявляй границы задачи и файлов в описании PR. При пересечении границ второй агент
  ждёт merge первого и обновляет свою ветку до начала правок.
- Один PR — одна задача. Коммиты — Conventional Commits.
- После обрыва восстанавливай фактическое состояние из Git/PR, не повторяй действия по
  памяти. Исполняемая памятка — `.claude/commands/obriv.md`.

**Git — механизм координации между моделями.** Чат одной модели не является источником
истины для другой: долговечные решения живут в документации и ADR, состояние
незавершённой работы — в `docs/SESSION_HANDOFF.md`, история — в коммитах и PR.

## Как читать памятки `.claude/commands/`

Файлы `.claude/commands/*.md` (`start`, `close_session`, `obriv`, `design`) — исполняемые
памятки, применимые **любому** агенту, несмотря на имя каталога. Правила перевода на
язык, независимый от инструмента:

- поле `allowed-tools:` — игнорировать, это конфигурация одного инструмента;
- `/команда` — читать как «выполни шаги, описанные в файле `.claude/commands/команда.md`»;
- гейт, описанный через конкретный инструмент (например «спроси через `AskUserQuestion`
  перед необратимым действием») — читать как «задай вопрос и дождись явного ответа».

**Форма любая, шаг обязателен.** Отсутствие у агента named-инструмента не отменяет шаг:
это предохранитель, а не фича вендора.

## Какие AI-файлы хранить в Git

Коммитить: `AGENTS.md` (источник истины), `CLAUDE.md` и `GEMINI.md` (короткие адаптеры),
`.claude/commands/` и `.claude/settings.json` (общие безопасные команды и разрешения),
`docs/`, `mailbox/`, `web/.env.example`.

Не коммитить: `.claude/settings.local.json` (локальные разрешения), кэши и сессии
`.codex/`, `.gemini/`, `.env*` с реальными значениями, ключи, токены, логи, временные
планы вне проектной документации.

Секреты не должны попадать в репозиторий даже под защитой `.gitignore`.

## Чего не делать

- Не писать и не коммитить в `../brain_matrica` — он read-only.
- Не ходить на чужие прод-боксы (ADR-0009 «чужой прод — не наш прод»). Наш — Бокс 1.
  Пересечение границы возможно только с явного разового разрешения владельца, и его
  надо зафиксировать письмом в `mailbox/to-brain/`.
- Не городить обходы недостающих доступов: неработающий канал, замаскированный обходом,
  живёт годами. Отсутствие доступа — повод написать письмо, а не изобрести путь мимо.
- Не публиковать автоматически контент из ВК: ingest по умолчанию создаёт **черновик**
  (mandate 07-26). Явная публикация — осознанное действие оператора флагом `publish`.
- Не выдавать непроверенное за проверенное: если гейт не удалось прогнать, это надо
  сказать словами.
